# 作者作品请求次数复现

小红书封面下载的隔离检查：

```sh
node scripts/test-xhs-cover-download.mjs
```

执行生产下载辅助函数并模拟网络响应，验证三路并发上限、小红书仅走代理并携带 `image_mode=xhs_cover`、失败释放槽位及其他平台直连兼容性，不访问实际接口。

在项目根目录执行，无需安装额外依赖：

```sh
node scripts/reproduce-profile-requests.mjs
node scripts/reproduce-profile-requests.mjs --total 1059 --timeline /tmp/profile-request-timeline.json
```

脚本从当前 `src/components/ProfileFetch.vue` 提取分页、轮询、取消及结束函数，在 Node VM 中执行。后端、整个写表函数、SDK 存储和时间均为模拟，不会访问实际接口或修改飞书表格。生产代码提取失败、请求次数不符、未完成任务或写入总数不符时以失败退出。

1059 条结果，当前每页上限 20 条，结果如下：

| 场景 | post/list 次数 | 有数据响应 | 空响应 |
| --- | ---: | ---: | ---: |
| 后端已完成、全部结果就绪 | 54 | 53 | 1 |
| 已完成，第一批写表时点击停止 | 54 | 53 | 1 |
| 每轮状态查询新增 10 条结果 | 107 | 106 | 1 |
| 前 60 轮暂无结果，随后全部就绪 | 114 | 53 | 61 |
| 写表失败 60 次并传回轮询层，随后成功 | 114 | 113 | 1 |

最后一次空响应用于确认结果排空。20 是每页上限，不保证每次返回 20 条；采集中可能产生较多不满页响应或空响应，因此总次数大于 54 不直接证明异常。

时间线记录虚拟时间、状态响应、每次 post/list 的 task_id、after_id、返回条数、next_cursor、has_more，以及模拟写表开始/完成/失败和取消响应。虚拟时间不是客户实际请求时间；模拟 cursor 使用记录序号，不代表真实后端 cursor 的格式。

写表失败场景特指错误已经从 `createAndWriteData` 传回 `pollStreamTask`：此时 cursor 未推进，下一轮会重新读取同一页。脚本没有执行真实附件转换、SDK 写入或写表函数内部的自动建表递归重试，也没有模拟多个实例和恢复状态保存失败。这里的 60 次失败是构造的复现条件，不代表客户确实发生了 60 次失败。

核对客户 114 次请求时，先统计空响应数量和每次返回条数，再按实际 cursor 比较：正常成功写表后下一请求应使用上一页 next_cursor；同一 after_id 多次返回同一批非空结果则需检查写入错误、恢复及多实例。仅看到相同 after_id 的空响应可能是正常等待采集。
