# 输出表配置的保存规则

适用：作品详情获取、获取作者信息、获取作者作品。

热榜主页面也沿用以下约束：选择目标表、读取回填不触发自动保存；配置与字段读取成功且草稿属于当前目标表时，才开放映射编辑、执行和修改保存。读取失败保留草稿，局部显示重试，不将失败视为空配置。同表修改通过已有保存队列顺序提交，提交前固定映射内容。热榜的目标字段下拉保留展示其他已勾选输出字段占用的列，并置灰提示占用者；占用同时包含默认同名写入和自定义映射，当前输出字段自身不占用自己的选项。执行前按目标表最新字段校验同列冲突，在修改表格前提示调整映射。新建表格只使用默认字段，不应用旧表映射。

1. 主页面的完整修改自动保存；任务弹窗只在点击保存时提交。
2. 主页面和弹窗分别持有映射草稿、字段选项；打开、编辑或取消弹窗不改动主页面草稿。
3. 主页面草稿记录所属表 ID。目标表尚未加载完成时，不允许把旧草稿写入新表。
4. 每次提交立即复制目标表、写入方式和映射。同表按提交顺序发送，不同表互不取消；失败提示沿用页面原逻辑，不自动重试。
5. 配置和字段列表只接收各自最新一次读取的结果；旧请求成功或失败都不覆盖新结果，主页面与弹窗的字段读取互不取消。关闭或重新初始化弹窗时，旧弹窗的配置和字段读取立即失效。
6. 读取失败保留原配置并阻止覆盖保存。成功读取且没有映射时，可以正常保存空映射。

三个页面使用 `createTableConfigSaver` 固定提交内容及同表顺序。页面负责配置读取、校验和请求，不再维护延迟定时器、待保存草稿或卸载补存。

本次整理不改变后端接口，也不改变输入筛选、任务启停和定时规则。输出表配置和定时任务仍通过两个既有接口保存，不承诺跨接口原子性。

验证命令：`node --test tests/*.test.mjs`。测试覆盖读取失败、草稿隔离、切表、连续修改、同表请求顺序以及失败后继续保存。

三个页面的任务弹窗：目标表配置及字段加载完成前，禁用写入方式、映射编辑和保存；提交时确认草稿所属表与当前目标一致。读取失败不开放保存，点击局部提示中的“重试”重新读取当前目标表。加载中在选表下方显示小转圈和“正在加载表格配置…”，失败时同处显示重试提示，成功后隐藏。当前表没有选表控件时放在字段映射上方，底部不重复提示。

编辑任务时，先用任务快照填好草稿并打开弹窗，再读取目标表配置；表格列表读取不阻塞弹窗显示。加载期间沿用局部提示和保存限制，取消或重新打开后，旧打开流程不再继续更新当前弹窗。

点击保存任务时固定任务 ID、表单、字段映射和字段选项，后续请求使用本次提交副本；保存期间禁止重复提交、编辑和关闭（取消、关闭按钮、Esc、遮罩），成功或失败后恢复操作。失败保留草稿，不自动重试。

立即执行期间，三个获取页统一锁定主表单配置区域；停止按钮位于锁定区域外。提交、执行和停止等待期间保持锁定，结束或失败后按现有运行状态恢复。作品详情和作者信息的逐行写入使用执行开始时复制的字段映射和写入方式，避免后续草稿变化影响同一批数据。
